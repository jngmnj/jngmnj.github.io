<li><strong>Modifier</strong>: Block이나 Element의 변형</li>

<h3 id="oocss의-장점-0kk">OOCSS의 장점</h3>
<ul>
<li><strong>재사용성</strong>: 작은 객체들을 조합하여 다양한 컴포넌트 생성</li>
<li><strong>유지보수</strong>: 구조와 스타일이 분리되어 수정이 용이</li>
<li><strong>성능</strong>: 작은 CSS 파일들로 인한 빠른 로딩</li>
<li><strong>확장성</strong>: 새로운 스킨을 쉽게 추가 가능</li>
</ul>
<h3 id="oocss의-단점-7vz">OOCSS의 단점</h3>
<ul>
<li><strong>학습 곡선</strong>: 객체지향 개념 이해 필요</li>
<li><strong>복잡성</strong>: 많은 작은 클래스들로 인한 관리 복잡성</li>
<li><strong>일관성</strong>: 팀원 간 일관된 사용법 유지 어려움</li>
</ul>

<h2 id="실무에서의-선택-기준-q7y">실무에서의 선택 기준</h2>
<h3 id="bem을-선택하는-경우-tfw">BEM을 선택하는 경우</h3>
<ul>
<li>팀원이 CSS 방법론에 익숙하지 않은 경우</li>
<li>빠른 프로토타이핑이 필요한 경우</li>
<li>명확한 명명 규칙이 필요한 경우</li>
</ul>
<h3 id="oocss를-선택하는-경우-x1r">OOCSS를 선택하는 경우</h3>
<ul>
<li>높은 재사용성이 필요한 경우</li>
<li>작은 컴포넌트들을 조합하는 경우</li>
<li>성능 최적화가 중요한 경우</li>
</ul>
<h3 id="smacss를-선택하는-경우-ocz">SMACSS를 선택하는 경우</h3>

<li>대규모 프로젝트인 경우</li>
